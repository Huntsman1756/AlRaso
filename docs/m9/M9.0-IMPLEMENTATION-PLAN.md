# M9.0 Reproducible Product Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deterministic, development-only Playwright/Chromium QA harness that executes the 14 approved M9.0 scenarios across three viewports twice, captures structured evidence, inventories architecture/quality/performance, and produces a canonical baseline without changing AlRaso product runtime behavior.

**Architecture:** Keep Node and Playwright isolated under `qa/browser/`. Playwright launches the frozen real Python webapp, freezes the browser clock, records network/console/page evidence, and treats reproducible product defects as findings rather than harness failures. A product-drift guard protects `webapp/**` and `alraso/**`; a two-run comparator normalizes only declared volatile fields and blocks closure on harness/environment/non-reproducibility errors.

**Tech Stack:** Node.js `24.19.0`, npm `11.17.0`, `@playwright/test` `1.63.0`, Playwright-managed Chromium `153.0.8010.12`, Python `3.12.10`, GitHub Actions `ubuntu-24.04`, existing stdlib AlRaso webapp.

**Spec:** `docs/m9/M9.0-BASELINE-SPEC.md` at `docs/m9-baseline-spec@27fd62d52ec93dfed800e078c1ce88b3a4ec0d3c`

## Global Constraints

- `product_commit = 2491d7d5e4e90d380b45c4baee3f2d023008b1a4`.
- `baseline_now = 2026-09-12T07:20:00+02:00`.
- Locale `es-ES`; timezone `Europe/Madrid`; device scale factor `1`.
- Canonical viewports: `1440x900`, `390x844`, `360x800`.
- Canonical matrix: `14 × 3 = 42` scenario/viewpoint combinations.
- Two consecutive canonical runs use the same product commit, harness commit, clock, scenarios, versions and runner job.
- `webapp/**` and `alraso/**` are immutable throughout M9.0.
- `LEGAL=FROZEN`; `M7=PAUSED`.
- Do not install Rasterio or `alraso[dem]` in the canonical M9.0 job.
- Successful product/API/weather responses are never mocked. S09 and S14 may abort real transport only.
- Product assertion failure is recorded as `scenario_status=FAIL` plus an evidence-backed finding; it does not become a harness error and does not by itself stop evidence collection.
- `HARNESS_ERROR`, `ENVIRONMENT_ERROR`, and `NON_REPRODUCIBLE` are baseline blockers.
- Never auto-accept visual changes or rewrite the canonical baseline from ordinary CI.
- No product fix is allowed while executing this plan.

- [ ] **Step 3: Implement the guard**

Create `qa/browser/helpers/product-guard.mjs`:

```js
import { execFileSync, spawnSync } from 'node:child_process';
import { PRODUCT_COMMIT } from './constants.mjs';

export function classifyProductDrift({ diffExit, status }) {
  const reasons = [];
  if (diffExit !== 0) reasons.push('tracked_product_diff');
  if (status.trim()) reasons.push('product_worktree_not_clean');
  return { clean: reasons.length === 0, reasons };
}

export function assertFrozenProductClean(root) {
  execFileSync('git', ['cat-file', '-e', `${PRODUCT_COMMIT}^{commit}`], { cwd: root, stdio: 'pipe' });
  const diff = spawnSync('git', ['diff', '--quiet', PRODUCT_COMMIT, '--', 'webapp', 'alraso'], { cwd: root });
  const status = execFileSync('git', ['status', '--porcelain=v1', '--untracked-files=all', '--', 'webapp', 'alraso'], {
    cwd: root,
    encoding: 'utf8'
  });
  const result = classifyProductDrift({ diffExit: diff.status ?? 2, status });
  if (!result.clean) {
    throw new Error(`ENVIRONMENT_ERROR product drift: ${result.reasons.join(',')}`);
  }
}
```
