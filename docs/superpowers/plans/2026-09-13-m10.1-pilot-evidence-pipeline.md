## 1. Reglas de ejecución

Cada tarea sigue el gate atómico de M9.2:

```text
test RED (contrato) → implementación mínima → test GREEN →
regresión relevante → commit → siguiente
```

Reglas adicionales específicas de pipeline:

- **Los tests NUNCA tocan red.** Los fetchers se prueban contra los bytes de
  evidencia G0 ya commiteados (`discovery/evidence/spain-coverage-g0/`) —
  son fixtures grabados con provenance real. El acceso en vivo es solo para
  el verificador (`tooling/m10_*_verify.py`), que corre manual/como job
  separado y reporta `reachability_observed` / `fetch_outcome`.
- **Nada de lógica jurisdiccional en providers compartidos**: si una tarea
  necesita `if jurisdiction == ...`, se detiene y se documenta — la
  peculiaridad va al `SourceProfile` o a un recipe nuevo.
- **Soft-404 siempre validado**: todo fetch exige `content_marker` del perfil;
  HTTP 200 sin marcador = `FAIL`, nunca éxito silencioso.
- **Geometría/PDF oficial**: `DIGEST_ONLY`/`METADATA_ONLY` por defecto; la
  evidencia almacena digest + URL re-fetcheada, salvo reuse verificado.
- Una tarea que descubra que la spec miente en algo: STOP, documentar,
  actualizar spec — no improvisar.

## 2. Layout previsto (único subtree nuevo)

```text
pipeline/

                       # ParsedInstrument, VersionClaim, GeometryEvidence,

  profiles.py          # loader + validación de SourceProfile (schema JSON)
  providers/

    geometry.py        # GeometryProvider OAPN WFS (fetch + digest)

                       #   boc_toc_post, dogc_socrata, boc_canarias
    fetch.py           # DocumentFetcher genérico (recipe-driven) + recetas
    parse.py           # DocumentParser por formato: bocyl_xml, boc_daily_xml,
                       #   akn, boe_xml, pdf_text, html_marker
    version.py         # VersionResolver: gazette_publication |
                       #   consolidated_api → RESOLVED|REQUIRES_MANUAL_REVIEW
  review.py            # ReviewGate: evidence bundle → ReviewPacket (artefacto)
  sources/
    bocyl.profile.json boc-cantabria.profile.json boa.profile.json
    dogc.profile.json  boc-canarias.profile.json
  schemas/
    source-profile.schema.json
    evidence.schema.json
tooling/m10_probe_verify.py   # generalización de g0_probe_verify por perfil
tests/test_m10_*.py           # contratos por capacidad + whitelist stanza
discovery/evidence/m10.1-*/   # salida reproducible de cada piloto
```

Dependencias: **stdlib only**. Los perfiles son JSON (`*.profile.json`):
PyYAML existe solo en el extra experimental `axiom` y la pipeline no se
acopla a `alraso[axiom]`; la validación es un validador estructural pequeño y
explícito en `profiles.py` (no se reimplementa JSON Schema completo).
`pdftotext` sigue siendo herramienta externa opcional — el parser PDF declara
`available=False` limpio si falta el binario.

### Task 2 — `SourceProfile` schema + loader

### Task 3 — `DiscoveryProvider` BOCyL (P1)

- `bocyl_opendatasoft`: query dataset → `DocumentRef[]` (campos verificados en

- RED con fixture: `bocyl-dataset-meta.json` + XML head de G0.

### Task 4 — `DocumentFetcher` genérico + reachability

- Recipe-driven: `GET` simple, `POST-then-GET`, `cgi`. Reporta por separado
  `reachability_observed` (¿respondió el servidor?) y `fetch_outcome` (¿qué
  devolvió?), más `runner_network` (env `ALRASO_RUNNER_NETWORK` ∈
  `{fixture, es_local, foreign_ci, unknown}`, default `unknown`),
  `observed_at`, `evidence_sha256`.
- Mapeo congelado: cualquier respuesta HTTP con status no-2xx → `REACHABLE` +
  `HTTP_ERROR` (status registrado); 2xx + `soft_404_marker` del perfil →
  `REACHABLE` + `SOFT_404`; 2xx sin `content_marker` → `REACHABLE` +
  `CONTENT_MARKER_MISMATCH` (nunca éxito silencioso); timeout →
  `UNREACHABLE` + `TIMEOUT`; error de transporte sin respuesta →
  `UNREACHABLE` + `TRANSPORT_ERROR` (`BLOCKED` solo con evidencia de
  intermediario); `UNKNOWN` solo si no se emitió intento.
- `content_marker` obligatorio por perfil.
- RED: bytes fixture + marcador → `SUCCESS`; marcador ausente →
  `CONTENT_MARKER_MISMATCH`; fixture soft-404 → `SOFT_404`; HTTP 404
  simulado → `REACHABLE` + `HTTP_ERROR`; timeout simulado → `UNREACHABLE` +
  `TIMEOUT`.

### Task 5 — `DocumentParser` formato `bocyl_xml` + ruta `pdf_text`

### Task 6 — `VersionResolver` mínimo

### Task 10 — Piloto P1 end-to-end (CyL/Picos)

- `python -m pipeline.run --profile bocyl --space pn-picos-de-europa`
  → `discovery/evidence/m10.1-p1-bocyl/` con bundle reproducible.
- Verificador en vivo `tooling/m10_probe_verify.py` extendido: corre el chain
  real y reporta PASS/FAIL/INCONCLUSIVE por eslabón.
- **Gate doble**:
  - `OFFLINE_REPLAY` = hard gate: fixtures exactos, hashes, parser, packet →
    PASS obligatorio.
  - `LIVE_VERIFY` = hard gate de ejecución, no de reachability: emitir el
    intento real es obligatorio. `REACHABLE` + contrato correcto → `PASS`;
    `BLOCKED`/`UNREACHABLE` esperado según perfil → `INCONCLUSIVE` (no bloquea
    merge); `REACHABLE` + contenido inesperado → `FAIL`; no se intentó →
    `FAIL`.

## 5. Fuera de scope explícito

- `VersionResolver.consolidated_api` completo (BOE/DOGC): M10.2+.
- Resolución de `vacatio` jurídica desde texto libre: M10.1 registra
  `effective_from=null` + `REQUIRES_MANUAL_REVIEW`; la interpretación es
  humana (Task 6).
- Fetcher ES-local real (infra): M10.1 solo declara `fallback` en perfil y
  registra `UNREACHABLE` honesto; la infra se decide con evidencia de P3.
- Inventario nacional completo (17 CCAA / ENP total): post-M10.1.
- Automatización de apertura de PRs (foul-flock pattern completo): M10.2+;
  M10.1 genera el `ReviewPacket` como artefacto, la PR la abre un humano.

## 6. Riesgos conocidos (de §M de la spec)

- PyYAML no es dependencia general (solo extra `axiom`) — perfiles en JSON
  con validador estructural stdlib (congelado en Task 2).
- `pdftotext` externo: parser declara `available=False` limpio.
- MITECO ALTCHA no se toca en M10.1 (inventario semilla = evidencia G0).
- BOC Cantabria en CI extranjero → `INCONCLUSIVE` esperado del verificador,
