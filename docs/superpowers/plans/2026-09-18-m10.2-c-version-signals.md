# M10.2-C — Version Signals (BOE/DOGC)

Approved spec: `docs/superpowers/specs/2026-09-16-m10.2-national-source-refresh-design.md` §C.3, §G(M10.2-C).

Goal: replace the honest M10.1 `consolidated_api` stub with mechanically
proven document-version signals for BOE and DOGC only. Output is VERSION
EVIDENCE — never legal truth, interpretation, or publication.

## 1. Verified live surfaces (probed es_local 2026-09-18)

### BOE — `boe_metadatos` signal

- `GET /datosabiertos/api/legislacion-consolidada/id/{BOE-id}/metadatos`
  with `Accept: application/json` → 200 JSON `data[0]`:
  `identificador`, `fecha_actualizacion` (ISO `YYYYMMDDT HHMMSSZ`),
  `fecha_disposicion`, `fecha_publicacion`, `fecha_vigencia` (YYYYMMDD),
  `vigencia_agotada` (N/S), `estatus_derogacion`, `estatus_anulacion`,
  `estado_consolidacion{codigo,texto}`, `url_eli`, `titulo`.
- `GET .../legislacion-consolidada?limit=N&from=&to=` → corpus listing
  keyed on `fecha_actualizacion` (change-detection window — recorded as
  evidence, not required for per-doc resolution).
- `GET .../texto/indice` → per-block `fecha_actualizacion` — granular
  signal recorded in evidence; block parsing is NOT implemented (spec:
  `boe_xml` only if required — metadatos suffices for the claim).
- Verified live: `BOE-A-2007-21490` (Ley 42/2007) → fecha_vigencia
  `20071215`, estado_consolidacion Finalizado. Bare `/id/{id}` returns
  400 under `Accept: application/json` (XML-only endpoint) — the
  resolver targets `/metadatos` only.

### DOGC — `dogc_socrata_eli` signal

- Socrata `n6hn-rmy7` row → `vig_ncia_de_la_norma` ("Vigent"/"Derogada"),
  `data_del_document`, `data_de_publicaci_del_diari`, ELI `url_format_xml`.
- `GET <eli>/dof/cat/xml` → 200 after redirect to
  `portaldogc.gencat.cat/utilsEADOP/AppJava/AkomaNtoso?idNumber=N&idVersion=V`
  — the effective URL carries `idNumber`/`idVersion` (verified live:
  es-ct/d/2003/02/04/39 → idNumber=309790, idVersion=318062).
- AKN body carries `FRBRuri`/`FRBRthis` ELI values but NOT idVersion —
  the signal comes from the redirect URL, which requires capturing the
  effective URL in the transport response.

## 2. Architecture (minimal diff)

### 2.1 `pipeline/providers/fetch.py` — `TransportResponse`

Add optional field `effective_url: str | None = None` (default keeps
every existing call site/fake unchanged). `urllib_transport` sets it
from `resp.geturl()`. No header capture is invented.

### 2.2 `pipeline/providers/version.py` — `consolidated_api` real

Strategy dispatch is keyed on `profile.versioning["signal_source"]`:

- `boe_metadatos`: evidence `consolidated` mapping carries the verified
  `/metadatos` payload + provenance envelope. RESOLVED requires:
  `status.code == "200"`, `data[0].identificador == doc_ref.doc_id`,
  well-formed `fecha_actualizacion`, present `fecha_publicacion`,
  `estado_consolidacion` + `vigencia_agotada` present.
  `effective_from ← fecha_vigencia` (structured official field, not
  free text). `consolidated_state ← estado_consolidacion.texto` +
  `vigencia_agotada` recorded in resolver_evidence.
- `dogc_socrata_eli`: evidence carries the Socrata row + redirect
  resolution. RESOLVED requires: row `url_format_xml` ELI path ==
  `doc_ref.doc_id` ELI, `vig_ncia_de_la_norma` present, and effective
  URL parses to integer `idNumber`/`idVersion`.
  `effective_from` stays `None` — DOGC exposes no structured
  effective-date field (vigència is a status, `data_del_document` is
  document date). `consolidated_state ← vig_ncia_de_la_norma`.

Any missing/malformed/contradictory link → `REQUIRES_MANUAL_REVIEW`
with the failure reason in `resolver_evidence` — never an exception
for data problems, never a fabricated claim. `VersionError` stays for
unknown strategies/structurally unusable evidence.

RESOLVED means ONLY "document version mechanically resolved". No
`legal_rule_version`, no review-complete writes, no `official_status`
mutation — the resolver writes a `VersionClaim` and nothing else.

### 2.3 Profile changes (data only)

- `pipeline/sources/atlas/boe.profile.json`: `versioning.signal_source:
  "boe_metadatos"` (strategy already `consolidated_api`).
- `pipeline/sources/dogc.profile.json`: `versioning.strategy:
  "consolidated_api"`, `signal_source: "dogc_socrata_eli"`.
- `source-profile.schema.json`: allow optional `signal_source` in
  `versioning`.

### 2.4 `tooling/m102_version_probe.py` — live verifier + gate

- `probe --profile <p> --doc-id <id> --evidence-dir <d>`: fetches the
  signal surfaces via `urllib_transport` (BOE metadatos; DOGC Socrata
  row + ELI redirect), preserves response sha256 + timestamps +
  runner_network, builds the evidence bundle, calls `resolve()`,
  writes `claim.json` + `evidence.json`.
- `gate --evidence-root <d>`: asserts >= 2 RESOLVED per source with
  complete provenance fields; any malformed claim → FAIL.

### 2.5 Evidence

`discovery/evidence/m10.2-version/{boe,dogc}/<doc>/` — request, response
sha256, timestamps, identifiers, signal values, claim result. DOGC AKN
bodies recorded digest-only (large).

## 3. Tests (hermetic — committed fixtures, injected transports)

- BOE: verified metadatos → RESOLVED; provenance retained;
  fecha_actualizacion kept; malformed JSON → manual; missing
  fecha_vigencia/identificador → manual; id mismatch → manual;
  HTTP_ERROR/TIMEOUT evidence → manual.
- DOGC: verified socrata+idVersion → RESOLVED; ELI provenance retained;
  missing/malformed idVersion → manual; row/doc_id mismatch → manual;
  fetch failure → manual.
- Global: deterministic claim for same fixture; no network; no
  legal_rule_version/review-complete writes anywhere; alraso/ + webapp/
  + qa/browser zero diff; free-text vacatio → null + manual.

## 4. Explicit non-goals

No boe_xml block parser (metadatos suffices — deferred), no Socrata
query interpreter (resolver consumes supplied rows), no free-text
vacatio, no publication path, no M10.3.
