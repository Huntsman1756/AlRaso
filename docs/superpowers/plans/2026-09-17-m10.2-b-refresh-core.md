## 0. Contrato congelado (heredado de spec §B/§C.2/§G — no renegociable)

```text
SnapshotRecord =
  {source_id, surface_id, doc_id,
   raw_sha256, canonical_sha256,
   canonicalizer_id, canonicalizer_version,
   etag?, last_modified?,
   fetch_outcome, reachability_observed,
   observed_at, runner_network}

FIRST_OBSERVATION -> BASELINE_CREATED -> snapshot persistido -> sin packet

VALID FETCH + mismo canonicalizer:
  canonical same + raw same + transport metadata same -> SAME (log)
  canonical same + (raw cambia OR etag/last_modified)   -> CHANGED_TRANSPORT_ONLY (log)
  canonical cambia                                     -> CHANGED_CONTENT -> packet

canonicalizer id/version cambia -> REBASELINE_REQUIRED
  (NUNCA clasificado como cambio de contenido)

timeout/DNS/TLS/red -> UNREACHABLE (registrado, nunca borrado)
  persistente >= degraded_threshold -> ACCESS_DEGRADED -> packet de alerta
  UNREACHABLE NUNCA alimenta DISAPPEARED_SUSPECTED

404/410/soft-404 alcanzable >= absence_threshold -> DISAPPEARED_SUSPECTED
  -> packet de alerta; evidencia previa se conserva

marker/contract failure -> INVALID
  persistente >= invalid_threshold consecutivas -> packet de alerta

contadores por (surface_id x runner_network)
thresholds por perfil: absence_threshold / invalid_threshold / degraded_threshold

CANONICALIZER_GATE (bidireccional):
  known-noise fixtures      -> canonical NO cambia -> 0 FP
  semantic-mutation fixtures -> canonical DEBE cambiar -> 0 FN
  toda comparación conserva raw_sha256 + canonical_sha256 +
                             canonicalizer_id/version

ReviewPackets en: CHANGED_CONTENT, ACCESS_DEGRADED, DISAPPEARED_SUSPECTED,
                  INVALID persistente
SAME / CHANGED_TRANSPORT_ONLY / UNREACHABLE|INVALID bajo threshold /
FIRST_OBSERVATION: log solamente

apertura de PR: HUMANA — los packets son artefactos de revisión
NEW_RULES = 0; legal_rule_version writes = 0
tests herméticos; live solo en tooling verificador
```

## 1. Decisiones de diseño (dentro de la spec)

1. **`pipeline/refresh/`** — paquete nuevo (forecast §E). Cuatro módulos:
   `snapshots.py` (store), `canonicalize.py` (registro versionado),
   `classify.py` (máquina de estados), `packets.py` (alertas deterministas).
2. **Store**: append-only JSONL por `(source_id, surface_id, doc_id)` +
   `counters.json` por `(source_id, surface_id, runner_network)`. Local-first,
   git-friendly, determinista. Los snapshots de fuentes reales no se
   commitean; los tests usan `tmp_path`.
3. **Packets**: refresh opera sobre documentos de fuente, no sobre bundles de
   espacio protegido — `review.prepare_pr()` exige la cadena de 9 eslabones de
   un espacio y no aplica aquí. Se implementa `RefreshPacket` propio:
   JSON determinista (mismo input = mismo bytes; timestamps solo de
   `observed_at`), `publication_readiness="NO"` siempre. La especificación
   exige "packet determinista para revisión humana"; la forma packet propia es
   la lectura honesta — cuando un CHANGED_CONTENT pertenezca a un espacio
   trackeado, el runner puede además invocar `prepare_pr` con el bundle real
   (integración M10.3+).
4. **Canonicalizers**: registro `{id: {version: fn}}`, stdlib-only.
   - `identity@1`: canonical = raw (PDF, XML estructurado — sin ruido
     demostrado).
   - `html_volatile@1`: elimina solo ruido demostrado en los probes M10.2-A:
     `<meta name="csrf-token">`, atributos nonce, comentarios HTML con
     timestamp de generación, tokens `data-*` volátiles.
   Bump de versión = `REBASELINE_REQUIRED` por contrato.
5. **Clasificación de observaciones** (mapeo sobre `fetch_outcome` existente):
   `SUCCESS` → válido; `TIMEOUT`/`TRANSPORT_ERROR` → UNREACHABLE;
   `HTTP_ERROR` con status 404/410 o `SOFT_404` → ausencia alcanzable;
   otro `HTTP_ERROR` (5xx) y `CONTENT_MARKER_MISMATCH` → INVALID
   (fallo de contrato observable, no ausencia — 500 no prueba que el
   documento no exista).
6. **Semántica de contadores**: cada contador cuenta observaciones
   consecutivas de su clase por `(surface_id, runner_network)`; una
   observación de otra clase no lo resetea ni lo incrementa; un `SUCCESS`
   resetea los tres. Fail-closed: threshold ausente en perfil → default
   conservador 3.
7. **Refresh thresholds en perfil**: sección `refresh` opcional en
   `source-profile.schema.json` (`absence_threshold`, `invalid_threshold`,
   `degraded_threshold`, `canonicalizer_id`, `canonicalizer_version`) —
   misma mecánica que la sección `atlas` de M10.2-A.
8. **Sin providers nuevos**: refresh re-fetchea doc_ids conocidos vía
   `fetch()` existente (`get_simple` cubre todos los perfiles candidatos);
   el discovery interpreter no participa en refresh.
